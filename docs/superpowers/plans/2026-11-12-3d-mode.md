# 3D Mode Implementation Plan

**Goal:** Add a lazy-loaded, independently saved 3D posing mode with perspective guide and reproducible depth export, preserving default 2D behavior.

**Architecture:** A self-authored articulated 3D mannequin supplies world-space joint positions. Project visible points through the same perspective camera to the existing rig and renderer; capture numerical depth from its surfaces. Retain the existing prompt and provider boundary. No unlicensed pose_maker code or assets.

**Tech Stack:** ES modules, Three.js 0.164.1, Node tests, browser.

**Spec:** User task and pose PM architecture at `docs/superpowers/specs/2026-11-12-3d-mode-design.md`; explicit user requirements supersede unsupported third-image and invented finger guidance.

## Global Constraints

- Default 2D unchanged; 3D data isolated; figure-side IDs consistent.
- Lazy load Three.js; camera framing shared for guide/depth; clip invalid points.
- No provider change or extra model calls; five guides first, R2 one call only after root gate.
- No copyrighted reference images as model inputs; no unverified model assets.

## Review Focus

- Behind-camera and near/far points omitted rather than reflected.
- Aspect ratio and resize preserve shared framing.
- 3D saving does not mutate 2D history or fake finger gestures.
- Depth is actual camera-space distance, black background, documented mapping.
- 2D and existing provider request remain unchanged.

## Tasks

1. Test and implement camera projection/clipping and depth mapping, with neutral 3D rig coordinates.
2. Build interactive articulated volumetric mannequin, orbit, posing, camera and depth rendering; retain exact state.
3. Integrate lazy mode switch, export, persistence and existing guide/prompt flow without disturbing 2D.
4. Verify browser interaction, projection/depth and 2D regression; construct five research states and report; request R2 gate before any single call.
5. Review, commit, push branch, open draft PR, notify coordinators.
